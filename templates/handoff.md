# Development Handoff

## Initialization handoff

Use this when the one-time framework setup ends. It tells the user which rules and empty templates now exist and which product decisions intentionally remain open.

- Framework installed: `[rules and templates]`
- Filled from confirmed requirements: `[none or list]`
- Existing repository evidence used: `[files and commands]`
- Decisions still open for a later user-agent conversation: `[list]`
- Not done: `[feature implementation, unapproved design, or other exclusions]`

The source template stays blank. For an actual initialization report, copy this file to the project's agreed handoff location and fill only confirmed facts.

## Feature-slice handoff

Use this after later implementation work. Explain the visible result and the evidence in plain language, including layer-specific checks and limits.

- Completed user-visible outcome: `[To be confirmed]`
- Proven by: `[entry point, scenarios, evidence levels, environment]`
- Not proven: `[limits and skipped checks]`
- Not included: `[explicit exclusions]`
- Records updated: `[paths]`
- Next decision or step: `[one clear follow-up]`

Use simple language. A changed file list is evidence of edits, not evidence that the user's outcome works.
